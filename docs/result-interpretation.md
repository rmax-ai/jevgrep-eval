# Result interpretation

The primary outcome is `task_success`. The preregistered primary comparisons
are A1 minus A0 and A3 minus A0. A1 is a full-configuration availability
effect, not a claim that every run used Jevgrep. A2 and A4 are forced-first
diagnostics; A6 is a paths-only localization ceiling. A5 is deferred.

Mock and simulated output is labeled `simulated-fixture`, `protocol
demonstration`, and is never efficacy evidence. Retrieval-only metrics are
mechanics diagnostics, not end-to-end task claims. Patch similarity is
diagnostic only and never correctness.

Report claims must link run IDs, the analysis set, the digest chain, trace
coverage, and pricing basis. Partial coverage, leak detection, post-snapshot
mutation, network-probe failure, env failure, and missing receipts invalidate
the affected primary claim while retaining the run as an audit artifact.

Threats include task sample size, one fixed model, repository and language
selection, provider variation, cache state, and prompt sensitivity. A null or
negative result remains first-class. W1a does not make production,
superiority, equivalence, no-harm, language-specific, or repo-general claims.
